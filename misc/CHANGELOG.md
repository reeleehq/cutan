# Changelog

## 2026-10-06

- **Silhouette styles keep their faces readable, and a short turn on twos never vanishes** (an#273):
  - The Reiniger spec declares cut-out eyes (`live.characters.part_tints`: white scleras, since a part's tint replaces the root's). `tests/test_style_specs.py` checks each part against the nodes an offline character is built with.
  - A `turn` played by name gets the shot's `step_hz`; one whose halves are shorter than a step is a hard swap at its midpoint, not a squash a stepped frame catches edge-on (`turn` version 2).
  - The `cutan-style` skill says that when the script contradicts a style rule, the script wins, and the departure is told to the user.
- **A brow fall is recorded for `--strict-assets`** (an#283): the face pass records the expression aspect's fall to `expr.without_brows` once per character an expression moves the brows of, so `--strict-assets` refuses it, naming `face.brows` and the remedy. One rule (`brow_loss`) decides who records: only an overlay face whose binding moves brow slots it cannot act with; a baked face, a browless descriptor or a procedural rig records nothing. `an validate` uses the same rule and now passes the store's art probe, so brow art that is missing is reported too, not only a hat.
- **A silent expression shows its mouth** (an#253): the factory drew a `viseme@<form>` variant's smile as a shift of the whole mouth, so a silent `happy` held a neutral line. A variant now curves the mouth: the corners move against the middle by `SMILE_CURVE_GAIN` × the half width, a closed smile for `happy` and a frown for `sad`. The neutral set is drawn exactly as before; the golden factory digests are re-taken for the redrawn variants only. An expression (or dialogue `[emotion]`) whose form the character has no set for is said by `an validate` and by the compiler's silent-mouth hold, with `an character mouths <name> --variants <form>`. New characters only; re-make or `an character mouths` an existing one to redraw its variants.
- **Character tools, from the Reiniger end-user test** (an#272). `an character silhouette` renders each figure as the stage draws it (build, head scale, hat), tinted black on white, through `render_character_silhouettes`; it used to rasterise the composite `<name>.svg`, so two different figures compared at IoU 1.000. It writes to the project's `artifacts/silhouettes/`, never into the character's folder, so `publish` no longer ships it. `an validate` says when an expression's partial lid (`lid_open -0.45`) asks for an eyelid drawing the rig lacks (`HALF`, `WIDE`) and so shows the open lid (`lid_rung_problems`). A speech pulse beats on the line's word timings when it has them (measured on the audio), with viseme syllables only inside a word, so a head no longer dips in the breath before the first word.
- **`[angry 0.4]`** (an#253): the `[emotion]` sugar takes an intensity from 0 to 1 after the name, kept through `scene.md` as the core's `Dialogue.emotion_intensity` (an `DialogueSugar` field, thorwhalen/an#372), and the face solver scales the line's expression by it. A word or an out-of-range number is refused, with the form.
- **The offline and Rhubarb lip-syncs are free and repeatable** (cutan#29, an#311): both declare `repeatable = True` and `billed = False`, so `an cache gc` re-makes a missing viseme track in memory under the default `lipsync=offline` instead of skipping the knob set. Rhubarb gains `check_available()`, raising the typed `RhubarbNotFoundError` with the install hint, so a machine without the binary makes the line unkeyable rather than refusing the collection. Whisper stays undeclared (it downloads weights).
- **A figure with nothing to step with validates** (cutan#35): `an character validate` requires `leg_l`/`leg_r` only when a skin draws a leg slot. A figure that draws none gets an `info` note that it walks `glide`, with how to add legs, instead of two blocking errors. `an character contract` says so.
- **The style policy rides an's seams** (an#348): the policy pass leaves the policy in the compile products, and the `play` lowering reads it for a walk's extent and expansion, so the internal `_policy` walk arg (`POLICY_ARG`) is gone. A character's declared `gait`/`speech` goes to the core matcher as `declared=`, so the precedence is one flag in `an` (cutan#36). A declared speech that cannot be honoured now falls to the policy before the chain, as a walk's does. A policy entry's own args come from `Resolution.choice`. `an validate` reads the pack from the `styles` store: a malformed pack policy is an error once at `meta/style_pack`, and the walk checks and a `sequence`'s extents resolve under the same shot-over-pack policy the compiler uses. A `yaml shot` block's `policy` reaches the compile. `an character capabilities --style` is the core's `describe_asset(policy=)`: its JSON has `style` and per-aspect `under_policy` (was `under_style`), and the text names what a policy-chosen method needs.
- **The policy workaround is gone** (an#334 landed): `cutan.styles.policy.applicable_policy` is removed. The core matcher now treats a policy as an order and lists the entries it passed over (`Resolution.skipped`), which the walk and speech resolutions record as `policy_skip` entries exactly as before. The `play` and `expression` lowerings accept the compiler's `products` keyword (an#348), so `an` can start passing it.
- **The genre's vocabulary rows live in this skill** (an#354): `.claude/skills/cutan/SKILL.md` carries the generated table of the presets, methods and kinds cutan contributes (`python -m an.semantic.docs --write ... --owner cutout_animation`), checked by `tests/test_skill_vocabulary.py`; `an`'s skill lists only the core names, so a change here can no longer redden an `an` PR.
- **The public rig builder and a declared origin** (an#338, R1 of an#331): `CharacterDescriptor` is an `an.stage.rig.RigDocument`, so it carries the optional `origin` (omitted when unset; its own serializer calls `omit_unset_rig_fields`); `stage_extent` reads `an.stage.rig.rig_origin`, the compiler's rule; `validate_character` advises on an origin outside the view_box; the compile pass builds through the public `build_rig_subtree`/`part_probe`/`raster_digest`/`art_src` instead of the stage compiler's private names. Requires `an.genres.API_LEVEL` 3.

## 2026-10-05

- **Docs and coverage** (cutan#23, #24, #25): a legless figure glides, not rocks, everywhere it is said (the descriptor's `gait` field, the art-package skill, a test docstring); `misc/docs/locomotion_gaits.md` says what the gaits do (the hem halves tilt as mirror images, and swing like legs in profile; `waddle` and `bounce` move their legs by view; `rock` rocks about the origin; the `waddle` preset and the `waddle` gait are two things; South Park's `bounce` is declared per character until cutan#9); the gait test walks a `parts` rig with legs beside the legless placeholder, which `WALK_LEG_NAMES`'s comment no longer credits with legs.
- **A walk is never substituted silently** (cutan#17, #21, #22): a `profile` asked while the character shows a view its legs do not swing in is resolved without its side view (the chain, or a policy's next choice: `legs` by default), recorded and warned with the remedy (turn to the side first; the walk's own `view` arg poses the legs without swapping the art, so it does not count); a walk played on a part of a character is refused by `an validate` and the compiler; a legged gait asked of a prop glides, recorded and warned; a gait parameter the walk's gait never reads is an error for an explicit gait (a pinned choice's args included) and a warning for the descriptor's or the chain's.
- **`walk` is version 4** (cutan#14, #15, #16, #18, #20, on top of version 3 from cutan#13; every locomotion method is version 2; every shot that plays a walk re-renders): a one-step walk swings its limbs (their one extreme mid-step) instead of sliding; the `profile` body cycle is phased to the contacts (up before the first contact, down after the last; from three steps on the legs pass each other) and `bob` is its whole travel between two contacts; the sway of `waddle`, `rock` and `hem` leans onto the standing foot whichever way the figure faces (it follows the rest `scale_x`); an amplitude set to 0 writes no channel, so an authored move on that property runs untouched; the body lands with the landing tween, not a settling `set`, so an authored move that outlasts the walk no longer snaps it back.
- **A `sequence` waits exactly as long as the walk runs** (cutan#12): the walk's extent is resolved with the same gait (the author's, the descriptor's, or the chain's substitute) and the same drawn scale the expansion uses (`cutan.characters.methods.walk_preset_context`, read by the compiler's and `an validate`'s extent resolvers), so a descriptor-declared `shuffle`, a substituted gait or a `scale: 2` figure no longer starts the next action early or late.
- **The walk's drawn scale is the stage scale, not the pose at the play's start** (cutan#13; `walk` is version 3, every shot that plays a walk re-renders): `walk` takes `scale`, which the compiler fills from the built rig, so a walk that starts under a `pop_in` no longer crashes with "step_length must be positive" or hops 0 px, and a figure resized by an authored move strides as drawn. A scale that is not finite and positive is refused naming the scale.

## 2026-10-03

- **Locomotion gaits** (an#224, P10 of an#231): `walk` takes nine gaits, each a locomotion method with declared requirements — `legs`, `profile` (the four-pose profile cycle; needs `swap.view:side`), `shuffle`, `hem` (need `limbs.legs`), and `waddle`, `hop`, `bounce`, `glide`, `rock` (need nothing). The chain is `legs` → `glide`: a figure without legs now glides instead of rocking about its feet. Default lengths (`step_length`, `bob`, `hop_height`) scale with the figure's drawn scale (an#224's comment: `scale: 2` used to shuffle). `an validate` warns when a requested gait will not be used (`cutout.walk_gait`), naming what would enable it. `walk` is version 2. Classification: `misc/docs/locomotion_gaits.md`.

- **The rig presets move here from `an.motion`** (an#322): `nod`, `point`, `turn`, `face_toward`, `walk`, `waddle` and `speech_pulse`, with their defaults and the walk's limb names, are `cutan.motion`; the rig-free presets stay in `an.motion`. `cutan.motion.PRESETS` (the core's and the genre's) is the table a `play` resolves in. Moved verbatim: no preset expands differently, so no pixel moves. `an`'s preset tests moved with them (`tests/test_motion_presets.py`).
