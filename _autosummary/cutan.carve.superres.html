cutan.carve.superres

cutan.carve.superres¶

Super-resolution strategies: more pixels for a part carved from a low-resolution frame (cutan#110).

When the only copy of a frame is small (a 360p scan), a thin part such as a sabre’s blade is 3-5 px wide. carve(upscale=k) mattes at k``x and comes back to the source's resolution, so the part stays 3-5 px wide. A \*\*super resolution strategy** is applied to the crop *before* the matte, and the part **keeps its resolution**: ``carve(frame, superres="realesr-animevideov3") returns a part 4x the source’s size whose offset/scale (to_part) still map source pixels into it, so recipes, pivots and landmarks stay in the source’s pixels.

A strategy is any callable rgb -> rgb that returns the HxWx3 uint8 image a whole factor larger on both sides; the shipped ones are classes with a factor, a name and a recipe() (what provenance records, and what as_superres() builds the same strategy back from).

name

what it does

needs

resample

interpolation (no new detail): the matte’s resolution is kept instead of thrown away

OpenCV (cutan[carve])

realesr-animevideov3

Real-ESRGAN for anime/cartoon video (BSD-3), x4, in overlapping tiles: clean on flat cartoon art

onnxruntime (cutan[superres]); the 2.5 MB model is fetched once

 
>>> import numpy as np
>>> rgb = np.zeros((10, 12, 3), np.uint8); rgb[2:8, 3:9] = 200
>>> sr = as_superres({"superres": "resample", "factor": 2})
>>> sr(rgb).shape, sr.recipe()
((20, 24, 3), {'superres': 'resample', 'factor': 2, 'method': 'cubic'})

class cutan.carve.superres.RealESRGAN(model='realesr-animevideov3', *, path=None, overlap=16, session=None, providers=('CPUExecutionProvider',), download=True, sha256=None)[source]¶

Bases: SuperRes

Real-ESRGAN through ONNX Runtime, run in overlapping tiles.

model: a name in MODELS (its file is downloaded once into

models_dir() and checked by hash); path: a local copy of that same file (checked by hash too; never written to the recipe)

overlap: source px each tile shares with its neighbours (each side) session: an already-built onnxruntime.InferenceSession (or anything

with its run(names, feeds)), instead of loading the model; the recipe then says the pixels came from an injected session, not the pinned model, and cannot be replayed

providers: ONNX Runtime’s execution providers (a GPU’s first) download: fetch the model when it is not in the cache sha256: the model’s hash a recipe recorded: refused unless it is the one

MODELS pins for model (a replay never runs another model)

The model sees [0, 1] RGB in NCHW and returns the same ``factor``x. The image is mirrored at its border, so the edge tiles see context too.
