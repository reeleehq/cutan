cutan.pack

cutan.pack¶

Check a cut-out production pack with cutan’s own validators (cutan#87).

A production pack (the cutan-production-pack skill, cutan#86) is a folder shaped like an an project: scene.md, cast.sh (one an character ... command per line), assets/ (environments, props, voices, styles, optional redrawn character parts) and PRODUCTION.md. check_pack() builds a throwaway project from it and runs the real checks:

  1. lint every SVG drawing in the pack (root tag, size, forbidden elements, outside links), check that every picture (PNG, JPEG, WebP: plates, prop parts, reference sheets) is one, and the keys of every voice document;

  2. an init a scratch project and copy the pack over it, except redrawn character parts (a character folder with no character.json);

  3. run each cast.sh line, refusing anything but the factory commands and options the skill documents (no shell: the line is split and run directly);

  4. copy the redrawn parts over the factory’s (same file names, same root tag), check the voice documents with the engine’s own checks, then an character validate every character and an props validate every drawn prop;

  5. an validate --strict-assets the scene.

A step fails on an error in its output, not only on its exit status (the an commands exit 0 on some failures). The result is a PackReport: one PackCheck per step, each with its errors and warnings, so a caller (the skill’s validate_pack.py, the reelee connector’s check this pack tool) can print it or return it as data (PackReport.to_dict()). A pack that cannot be checked at all (no scene.md, a refused cast.sh line) is a report with one failed pack check, never an exception. Its notes say what is neither an error nor a warning: a pack whose drawings are all hand-written SVG gets one, since such art looks computer-made (cutan.art_brief says what to ask for instead).

Nothing is rendered: no browser, no network (an character new must say --offline), no paid call.

>>> report = check_pack("/no/such/pack")
>>> report.ok, report.summary()
(False, 'FAIL: 0/1 checks passed, 0 warning(s)')
>>> report.errors
['pack: pack has no scene.md: is it a production pack?']

cutan.pack.check_pack(pack_dir, *, workdir=None, an_command=('/opt/hostedtoolcache/Python/3.12.15/x64/bin/python', '-P', '-m', 'an'), python=None, timeout=300.0, deadline=900.0, child_limits=None)[source]¶

Check the production pack at pack_dir; return a PackReport.

pack_dir: the pack folder (scene.md, cast.sh, assets/, PRODUCTION.md) workdir: where the scratch project is built (default: a temporary folder,

deleted afterwards; given, it is kept, and the project is <workdir>/project)

an_command: how to run an (default: python -m an with this interpreter) python: the interpreter for the engine’s voice checks (default: the one in

an_command when it starts with one, else this one)

timeout: seconds one step may run before it counts as failed deadline: seconds the whole check may run (None: no limit) child_limits: called in every child process (each an step and the voice

check) just before it runs, as subprocess.run’s preexec_fn: a host caps memory or CPU once (resource.setrlimit) instead of wrapping one command. POSIX only (ValueError elsewhere); None: no limit. Keep it to resource.setrlimit with resource imported beforehand: preexec_fn can deadlock when it imports, logs or takes locks while the host runs threads. RLIMIT_AS is not enforced on macOS

The pack is untrusted: only PACK_SUFFIXES files are copied, the an children run without the working directory on their import path and without any secret-looking environment variable, the work is capped (MAX_CAST_LINES, MAX_ASSET_FOLDERS, deadline), and the report names no server path (the scratch project is <project>).

A pack that cannot be checked at all gives a report with one failed pack check; nothing here raises on a bad pack.

PackReport
