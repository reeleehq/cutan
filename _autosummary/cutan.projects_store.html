cutan.projects_store

cutan.projects_store¶

Where a cutan project’s files are read from and written to: a disk folder or S3, by configuration.

The library’s projects kind is a mapping relative path -> bytes (ADR-0024: s3://{bucket}/{tenant}/cutan/projects/{rel} mirrors ~/.local/share/cutan/projects/{rel} exactly, so both backends hold the same keys). projects_store() returns that mapping; materialize_project() returns a real folder for tools that need files (ffmpeg, a browser), reading through a cache under ~/.cache/cutan/projects/; push_project() is the write half (cutan#91): it writes what changed since the folder last synced, never over a newer version another machine pushed, can delete what the folder no longer has, and keeps derived output local.

A folder that belongs to a store carries the record .an/projects_store.json (STORE_RECORD): the store’s coordinates and, per file, the size and sha256 the folder last synced (files). The record is pushed with the project, so the store’s copy says what the store holds and the folder’s copy is the base a push compares both sides against (a three-way comparison: a file the folder did not change is never pushed over one the store changed, and a file both changed is a conflict that only force writes). an init <id> --id --genre cutout_animation creates a project in the cache folder with that record when the backend is S3 (new_project_dir(), the projects.dir.cutan service of an API level 7).

Configuration (environment; the first match wins, CUTAN_HOME always forces local):

  • CUTAN_HOME set: local, under that root (an explicit root beats any S3 setting)

  • CUTAN_PROJECTS_BACKEND=s3: S3, with CUTAN_S3_BUCKET (default tw-apps), CUTAN_S3_PROFILE (default tw-server) and CUTAN_S3_TENANT (default thorwhalen)

  • otherwise: local (the default)

cutan.projects_store.materialize_project(project_id, *, settings=None, store=None, cache=None)[source]¶

A real folder holding project_id’s files.

Local backend: the project folder itself, no copy. S3: files are read through into the cache and kept, and the folder records the store it belongs to (STORE_RECORD). A cached file is reused when its sha256 is the one the store’s record holds for it (a file the record does not know: when its size matches the object’s). The store wins: a cached file that differs is overwritten, so push a folder’s changes before pulling into it.

cutan.projects_store.new_project_dir(project_id, *, default=None, settings=None, store=None, cache=None)[source]¶

Where an init <id> --id --genre cutout_animation creates the project.

The projects.dir.cutan service (an API level 7): the core computes its own default (<root>/projects/<id>) and hands it over as default. Local backend: that default. S3: the cache folder, with what the store already holds under the id read through first (so an init sees an existing project’s scene.md and refuses to clobber it) and the record that the folder belongs to the store, which a later push_project() reads. Nothing is uploaded: the push is explicit.

cutan.projects_store.push_project(project_id, *, folder=None, settings=None, store=None, delete_missing=False, exclude=('.git/', '.an/render_work/', 'artifacts/shot_cache/', 'artifacts/shots/', 'artifacts/render_reports/', 'artifacts/probes/'), force=False, cache=None)[source]¶

Write folder’s files to the store under project_id/: the inverse of materialize_project() (cutan#91).

folder defaults to where materialize_project() puts the project: the cache folder on S3, the project folder itself locally (which is the store’s own copy, so that push does nothing). Each file is compared three ways: with the store’s record of it (the store’s copy of STORE_RECORD) and with the folder’s record (the base: what the folder last pulled or pushed; with no base, the store’s record stands in, so a first push from a folder with no history writes its differences). A file equal to the store’s is unchanged; one the folder changed and the store did not is written; one the folder did not change but the store did is stale and left alone; one both changed is a conflict, written only with force. A file the records do not know is compared with the store’s bytes when the key exists. exclude names what stays local (DEFAULT_PUSH_EXCLUDES); delete_missing deletes the store’s keys the folder no longer has (a key the store gained or changed since the base is kept, unless force); excluded files the folder still has are never deleted. The record is then written to the folder and, when anything changed, to the store.

Return type:

PushReport
